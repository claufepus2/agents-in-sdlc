GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、その作業をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を承認または拒否し、エディターを離れずに追加プロンプトで会話を方向付けたり、作業を調整したりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして承認します。
- セッション中にエージェントを方向付け、高コントラストモードに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティのカスタムエージェントが、高コントラストモードを実装しています。作業中にデザインチームから追加の要望がありました。標準のテーマが暗すぎると感じる利用者向けに、ライトモードの切り替え機能も追加します。新しい会話を最初から始めずに、既存のセッションを導いて作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが調べたファイル、実行したコマンド、提案した編集など、各ステップを確認できます。ファイルの編集は差分と **Keep** / **Undo** のコントロールとともにインラインで表示されます。

1. 演習 4 で開いた Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を承認するには **Keep** を選択します。
    - 変更を元に戻してエージェントに再試行させるには **Undo** を選択します。
4. チャット上部の **Files changed** 表示を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの呼び出しで許可が必要な場合 (たとえば、ターミナルコマンドの実行など)、エージェントは一時停止して **Allow** プロンプトを表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. 高コントラストモードの実装が完了するまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントを導いてライトモードを追加する

高コントラストモードが実装されたら、同じ会話でライトモードの切り替え機能を追加します。会話を続けると、エージェントは前の作業で変更したコンポーネント、使用したスタイル、設定した local storage の方法などのコンテキストを保持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは以前の変更を確認し、ライトモードの追加を提案します。
3. 高コントラストモードと同様に、新しい編集が提案されるたびにレビューして **Keep** または **Undo** を選択します。
4. エージェントが望まない方向に進んだ場合 (たとえば、切り替え UI を意図しない形にリファクタリングするなど) は、チャット入力欄の横にある **Stop** ボタンで停止し、補足のプロンプトを送ります。

> [!TIP]
> 進行中のセッションを導くほうが、最初からやり直すよりも速くなります。追加プロンプトを使って、「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」「3つ目の切り替え機能は追加せず、既存の設定パネルにライトモードを組み込む」のように方向を修正したり、「両方の切り替え機能にキーボードショートカットも追加する」のように範囲を広げたりできます。

## 作業内容をレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. いくつかのファイルを開いて差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による永続化など、アクセシビリティのパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで進行中のセッションを監視して方向付けました。ファイル編集を確認し、変更を承認または拒否し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または拒否しました。
- 追加プロンプトでセッションの進行中に方向を修正しました。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボ全体でローカルのカスタムエージェントが行った変更をレビューします。
